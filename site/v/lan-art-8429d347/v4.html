🔍 cc_deepseek 的 Cloud Agent Views 登录提示 — 根因与修复方案

herdr + 侧边 pane 实测复现 · 2026-08-07 · Claude Code 2.1.196 (claudefast-patched)

现象 你看到的

进入 cc_deepseek TUI 后按 ← 左方向键 进入 Agent Views（Agents 视图），在底部输入框发消息，新会话立即显示：

✻ list files in…    login required — run /login · Invalid API key · Fix external API key

打开会话后：

⎿  Invalid API key · Fix external API key

主对话（chat）完全正常 —— 只有 Agent Views 里创建的新会话报错。新开会话、进旧会话都一样。

复现 herdr 侧边 pane 实测

在 herdr 开了测试工作区 + 侧边 pane，完整走了一遍你的操作路径：

1
herdr pane 启动 claude --settings settings.deepseek.json（ccdpsk 等价）
2
send-keys left → 进入 Agent Views，显示会话列表 + describe a task for a new session 输入框
3
send-text + enter 发消息
4
复现：新会话状态 login required — run /login，打开后 Invalid API key

对照组：同样的环境直接跑 claude --bg "任务"，后台会话 正常完成 —— 说明问题只在 Agent Views 的会话创建路径。

根因 证据链（4 步）

① 分派进程丢了 ANTHROPIC_BASE_URL

Agent Views 创建会话时，实际进程由 共享 daemon spawn。对比进程环境变量：

进程ANTHROPIC_API_KEYANTHROPIC_BASE_URLANTHROPIC_AUTH_TOKEN
daemon（spawn 者）✓ DeepSeek key✓ api.deepseek.com/anthropic✓
分派出的会话✓✗ 丢失✗ 丢失

② 请求打到官方 API → 401

没有 ANTHROPIC_BASE_URL，SDK 默认 https://api.anthropic.com。DeepSeek key 打官方 endpoint → 401 Invalid API key。

③ 二进制代码定位（反编译事实）

daemon spawn 分派进程时做 env 净化，ANTHROPIC_BASE_URL 在过滤列表里：

// Yto（env 过滤列表）定义：
Yto = ["ANTHROPIC_BASE_URL", "_CLAUDE_CODE_ASSUME_FIRST_PARTY_BASE_URL",
       "ANTHROPIC_BEDROCK_BASE_URL", ...]
kVo = [...Qto, ...s$t, ...Yto, ...Jto, ...]   // BASE_URL 被收进 kVo

// daemon spawn 分派进程：
for (let a of kVo) if (!e.env?.[a]) delete i[a];   // ← 白名单没有 BASE_URL → 删掉
...
else if (s.ANTHROPIC_BASE_URL) delete i.ANTHROPIC_AUTH_TOKEN;  // AUTH_TOKEN 也被删

主进程传给 daemon 的 env 白名单只含 API_KEY + 模型，不含 BASE_URL（实测：即使主进程 OS env 里 export 了 BASE_URL，分派进程仍然拿不到）。

④ 为什么主对话正常

主对话由 ccdpsk 主进程自己跑，--settings settings.deepseek.json 的 env 直接注入自身 → DeepSeek 配置完整。只有 daemon 分派的会话走过滤链。

一句话根因：Agent Views 的分派会话由 daemon spawn，daemon 的 env 净化把 ANTHROPIC_BASE_URL 过滤掉了；第三方 endpoint（DeepSeek）没了 BASE_URL 就打到官方 API，DeepSeek key 无效 → 显示「login required / Invalid API key」。这是官方对第三方 endpoint 的兼容性缺陷，不是 DeepSeek key 的问题。

修复方案 请你抉择

方案 A · 推荐 · 治本 字节级 patch claudefast：保住 BASE_URL

给已有的 claudefast-patch（已做 200k 钳制解除补丁）加第二处字节补丁：把 Yto 过滤列表里的 "ANTHROPIC_BASE_URL" 等长替换为无效名 "ANTHROPIC_BASEURLX"（18→18 字符，已确认二进制中该序列唯一、可精确命中）。效果：daemon 分派进程保留 ANTHROPIC_BASE_URL → 请求发往 DeepSeek → Agent Views 会话正常。

  • ✅ 根治：Agent Views、未来所有 daemon 分派路径都正常
  • ✅ 与现有 patch 架构一致（claude 升级自动重建，仅需回归验证一次）
  • ⚠️ 需要重启一次 claude daemon（共享进程，重启瞬间其它后台会话短暂中断，自动恢复）
  • ⚠️ 若机器上官方版 claude 先起 daemon，过滤逻辑仍走旧代码 —— 需要保证 daemon 是 patched 版
方案 B · 保底 · 零风险 禁用 Agent Views

ccdpsk 函数里加 CLAUDE_CODE_DISABLE_AGENT_VIEW=1（二进制已内置支持：Disable agent view (claude agents, --bg, /background…)）。左键不再进入 Agent Views，回到普通对话。

  • ✅ 立即生效、零风险、不用动二进制
  • ❌ 失去 Agent Views（会话列表 / 后台任务管理 / 分派）功能
方案 C · 零改动 接受现状，用其它入口跑后台任务

Agent Views 里发消息会报错，但 --bg / /background 直跑正常（已实测）。后台任务用这些入口，Agent Views 仅当只读的会话列表用（点击"发送提示词"之外的浏览操作可用）。

  • ✅ 零改动
  • ❌ 体验差：Agent Views 的输入框是坏的，容易误触报错
