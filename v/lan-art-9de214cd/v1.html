业务工厂后端选型：Claude Agent SDK + AgentBay 沙盒 vs Sandbox B

来源：业务工厂 v3 设计（对话生成 App 代码 → 预览 → 部署）移植到 WinBrain Creator OS TUI · 2026-08-07
✅ 推荐：Claude Agent SDK + AgentBay 沙盒（沙盒 A）
设计的核心闭环（生成 → 预览 → 部署）直接命中 A 的既有能力；Web 业务工厂已经走 A，TUI 同路即双端一致；沙盒红线不变（仍是既有两套）。

一、两套沙盒对比

维度沙盒 A（AgentBay 云端）沙盒 B（本地 Expert Sandbox）
预览 / 部署✅ 内置：publish_preview + browser_takeover + 静态预览（端口 30100–30199，1h TTL）→ 直接对应设计的 Preview / Deploy❌ 无预览机制，需自建
现有业务工厂路径✅ Web 业务工厂已走 AgentBay SSE 构建/停止/预览（cloudAgentStream/startCloudPreview/stopCloudPreview）❌ 业务工厂无本地生成通道，从零接
工具面10 个白名单工具：bash / read_file / write_file + publish_preview / browser_takeover / stop_preview + ontology 4 个 — 够代码生成✅ 完整 Claude Agent SDK 工具集（更富）
隔离 / 安全云端多租户隔离；文件限 /tmp + /home/wuying（禁符号链接/隐藏条目）；上传校验 ≤1MiB/文件、禁 .env/.pem/.key；错误一律脱敏本地 lease + OS Sandbox + PreToolUse 双门禁 fail closed；10 分钟空闲销毁；不继承宿主环境变量
延迟 / 依赖远程往返，需 AgentBay key + 网络✅ 本地快、可离线
复用度✅ 复用 CloudAgentWorkbench 状态机（new/starting/ready/destroying）+ 云文件浏览器 + 会话恢复（/resume）✅ 复用 runCreator 机制（lease / 凭据 / 产物校验 / credential 扫描）

二、为什么业务工厂选 A

  • 闭环直通：生成（write_file/bash）→ 预览（publish_preview，端口+TTL 已实现）→ 部署（静态预览 = 设计 DeploymentModal 的后端）。沙盒 B 没有预览，要自己造。
  • 双端一致：Web 业务工厂已用 AgentBay 构建 — TUI 走同一条通道，不引入第二套构建体系。
  • 沙盒红线不变：仍是既有两套（A/B），只是业务工厂用例从 B 移到 A，与 Web 对齐。
  • 生命周期契合：应用代码是"生成 → 预览 → 丢弃"型资产，云沙盒的隔离边界天然合适，不留本地沙盒状态。
  • 沙盒 B 继续保留给：专家/员工/项目 Creator 生成、普通聊天、本地执行（完整工具集 + 离线 + 低延迟，现有机制成熟，不动）。

三、选 A 的代价（接受项）

  • 依赖 AgentBay key / 网络 — 无 key 时业务工厂生成不可用（fail closed，不造假生成，区别于 v3 设计的无 key 模板替换）
  • 生成延迟更高（远程往返）
  • 10 工具白名单比 B 的工具面窄（bash + read/write 可覆盖代码生成，但无 Edit/Glob 等）

四、落地设计（后端，不抄 UI）

App 生命周期

创建 App（既有 createApp） → 对话生成（新） → 预览（既有 publish_preview） → 发布版本快照（新） → 回退（新）

新用例（application 层）

  • generateAppCode(appId, prompt)：CloudAgentWorkbench 新会话 → AgentBay 沙盒内生成/修改代码 → 读取产物 → 校验（对齐现有上传规则）→ 存 app.files + 追加 ChatMessage（含 updatedFiles 变更清单）
  • publishApp(appId) / unpublishApp(appId)：跑 blocker（无文件不可发布）→ 存版本快照 → status 切换

域模型扩展

  • BusinessApp：+status: "draft"|"published"、+files: CodeFile[]、+messages: ChatMessage[]、+model
  • 纯函数：validateAppFiles（1–30 文件、大小上限）、appPublicationBlocker

接入点

  • HTTP：POST /api/v1/apps/:id/generate（对齐 v3 /api/chat 协议：prompt+files+history）、POST /api/v1/apps/:id/publish、GET /api/v1/apps/:id（带 files/status）
  • TUI：业务工厂 App 详情加「对话生成」+「发布/回退」两段流程，复用 creator 屏流式渲染模式

五、实施顺序

  • ① 域模型 + 用例 + 存储（含 headless 测试）
  • ② HTTP 端点（web 双端对齐）
  • ③ TUI 屏：对话生成 + 发布/回退
  • ④ 端到端验证（AgentBay 会话 smoke）
测试中心（TestCase 执行）与多目标部署超出 v1 核心 — 首版做「生成 + 发布」闭环。
