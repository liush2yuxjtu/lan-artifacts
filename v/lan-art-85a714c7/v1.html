1. 交付的功能

TUI 普通聊天 / 专家 / 员工会话支持从 手写配置文件 加载外部 HTTP MCP（无需改代码、无需点击选择）。 专家同时保留原有「从 Data Ontology 点击选择」的加载方式。

配置文件

config/mcp-servers.json              ← 提交的模板（占位 token）
config/mcp-servers.local.json        ← 本地覆盖（.gitignore，真实 token 放这里，同名键优先）
{
  "mcpServers": {
    "winbrain-yuntu": {
      "type": "http",
      "url": "http://192.168.26.166:3010/mcp/projects/yuntu-competitor-analysis",
      "headers": { "Authorization": "Bearer wbmcp_替换为同事自己的Token" },
      "alwaysLoad": true
    }
  }
}
  • 当前仅支持 type: "http"（stdio 子进程会继承宿主环境，违反 Sandbox B 基线，暂不开放）
  • 配置经 composition 校验注入，聊天会话 mcpServers 自动合并，工具名为 mcp__<配置键>__<工具>
  • 新增验证入口：npm run smoke:mcp（真实模型调用）与 node --import tsx scripts/mcp-tool-count.ts（免模型装配探针）

get_context_pack 返回的核心关系证据

关系证据（返回上下文包）
云图账号 ↔ 系统品牌QC_MATERIAL_YUNTU_BRAND_ACCOUNT.SUB_ACCOUNT_ID = QC_MONTAGE_BRAND.BRAND_ACCOUNT_ID（1:1），云图子账号与系统品牌一一对应，是竞品策略配置的身份上下文
云图账号 → 品类/品牌QC_MATERIAL_YUNTU_CATEGORY、QC_MATERIAL_YUNTU_BRAND 均按 BRAND_ACCOUNT_ID = SUB_ACCOUNT_ID 关联（1:N）
视频 ↔ 素材竞品视频存于 QC_MONTAGE_YUNTU_VIDEO_DATA（VID 云图素材唯一标识 / VIDEO_ID / VIDEO_OSS_URL / SCRIPT_CONTENT 脚本文案）
素材 ↔ 品牌标签QC_MONTAGE_YUNTU_VIDEO_BRAND_TAG.TAG_ID → QC_MONTAGE_BRAND_MATERIAL_TAG.ID（N:1），同一标签体系复用本品与竞品两条业务线，支撑跨品牌可比性分析与智能混剪推荐

3. 部署侧缺口（需张晴确认）

参考网关 POST-only，缺 Streamable HTTP GET/SSE。
部署在 192.168.26.166:3010 的网关（winbrain_os-template apps/ontology-mcp-gateway）路由只接受 POST： 
if (request.method !== "POST" || !match?.[1]) {
  sendProblem(response, 404, "ONTOLOGY_MCP_NOT_FOUND", ...);
}
Claude Code 客户端流程：POST initialize（成功）→ GET 开 SSE 流 → 404 → 连接被丢弃（CLI 日志 Failed to open SSE stream: Not Found）→ 工具不可用。

修复方向（已验证模式）

  1. 按 mcp-session-id 维护 transport 会话（本仓库 src/adapters/inbound/mcp/data-ontology-http.ts 已是该模式，并用 CLI 实测：17ms 连接、无 SSE 错误、175s 干净关闭）
  2. GET + 有效 session → 转发 transport.handleRequest（SSE 流）；DELETE → 关闭并清理
  3. 注意：audit 绑定 DB 事务（withOntologyMcpProjectTransaction），会话存活期内需保持事务或改用连接池写审计

部署侧修复后运行 npm run smoke:mcp 即作为全链路验收。

4. 本机环境备注

本笔记本 node 进程无法直连 192.168.26.x（EHOSTUNREACH；curl / python / nc / bun 均可），疑为企业网络策略；CLI 的 MCP HTTP 客户端运行在 node 上，且 Sandbox B 规则要求 SDK env 显式空对象、代理变量未透传。网关修复后若仍不加载，需二选一：网络策略放行 node 内网直连，或评审放宽 env 仅透传非敏感代理路由变量（涉及既有安全测试断言）。
